# v3.0.0 migration guide

This document summarizes relevant changes between OSS Policy Kit **v2.x** and **v3.0.0**.

## JSON contract `reports/0.1` -> `reports/0.2`

- **`schema_version`** now ends with **`/reports/0.2`** by default.
- **`live_collection`** is an optional top-level object (or `null` when no live collection metadata exists).
- **`results[].evidence_collection_method`** is now `live` \| `manual` \| `static` (default `static` for clone-only evaluation).
- **`results[].deprecation_note`** is present when a control is **`deprecated`** in the catalog.

To keep the legacy **0.1** contract (without the fields above), use:

```bash
python -m oss_policy_kit evaluate --target . --profile github-level-1 --report-json-contract 0.1
```

## Promoted or deprecated controls

- Multiple controls moved from **`experimental`** to **`stable`** (see `catalog.yaml` and `CHANGELOG.md`).
- **`SEC-AUDIT-016`** and **`CI-SBOM-017`** are now **`deprecated`** with **`deprecation_note`** — evaluators still run, but lifecycle now signals that YAML-only heuristics are not strong proof.

## Optional dependencies

- **`pip install 'oss-policy-kit[github]'`** (or `httpx` directly) for **`collect-evidence --platform github`**.

## New subcommands

- **`collect-evidence`**: collect GitHub evidence via API.
- **`diff-reports`**: compare two **`evaluation-report.json`** files.

## Evaluator plugins

Register entry points in the **`oss_policy_kit.evaluators`** group (see comments in **`pyproject.toml`**). The entry-point name must match the **control ID**; overriding built-in controls is not allowed.

## External profiles

`--profile` accepts a path to a **YAML** file validated by **`profile-spec.schema.json`**.

## Manual vs automatic evidence

- **`scaffold-evidence`**: **manual** mode (templates).
- **`collect-evidence`**: **automatic** mode (GitHub).
