# Migration guide: v5.1.0 → v5.2.0

v5.2.0 is an **additive minor release** in the `5.x` line. No breaking changes; the JSON wire contract `reports/1.0` is byte-stable.

## What's new

### One new profile — `cra-eu-ready-1`

Multi-platform advisory profile mapping the kit's controls to **EU Cyber Resilience Act** preparation. **First non-platform-prefixed profile** in the catalog.

```bash
python -m oss_policy_kit evaluate --target . --profile cra-eu-ready-1 \
  --output-dir ./out/cra --fail-on degraded
```

12 controls. Posture: `advisory`. Recommended `--fail-on`: **`degraded`** only — the profile is regulatory mapping, not a release gate.

### Two new controls (lifecycle: `experimental`)

- **`GH-RUNNER-062`** (assurance: `signal`) — self-hosted runner posture. Direct response to the 2026-03 trivy-action incident.
  - **FAIL** when PR-triggered workflows use `runs-on: self-hosted`.
  - **manual-review-required** when self-hosted is used without the `ephemeral` label.
  - **PASS** when all self-hosted workflows include `[self-hosted, ephemeral]`, or when no self-hosted is used at all.
  - Optional evidence-backed layer via `.oss-policy-kit/evidence/runner-groups.json` (new schema).
  - Wired into `github-level-2`, `github-level-3`, `github-release-hardening-2`, `github-release-hardening-3`.

- **`RELEASE-ARCHIVE-063`** (assurance: `signal`) — release archival/retention policy.
  - Signal: detects `RELEASE_ARCHIVAL.md`, `.github/release-archival.yml`, or a "release archival" / "retention policy" section in `docs/release-readiness.md`.
  - Evidence: `.oss-policy-kit/evidence/release-archival-policy.json` with `retention_years` (≥10 aligns with EU CRA), `archive_destination`, `vulnerability_handling_doc`.
  - Wired into all `*-release-hardening-3` profiles + `cra-eu-ready-1`.

### Loader / `profiles --format json` maturation

- The loader now accepts profile IDs without a platform prefix.
- `profile-list/v2` emits `family: "multi"` and `posture: "framework_aligned_advisory"` for regulatory profiles.
- `--family multi` is a valid filter on the `profiles` subcommand.
- `recommend-profile` skips non-platform profiles — regulatory mappings are not heuristic recommendations.

### Evidence schema additions

- `evidence-runner-groups.schema.json` (v1).
- `evidence-release-archival-policy.schema.json` (v1).

Both mirrored under `reports/schema/`.

## What did NOT change

- The 20 v5.1.0 profile IDs (now 21 total with `cra-eu-ready-1`).
- All v5.1.0 control IDs (now 69 total: 65 v5.0.0 + `AUDIT-STREAM-060`, `PROV-VERIFY-061`, `GH-RUNNER-062`, `RELEASE-ARCHIVE-063`).
- `--fail-on` semantics, exit codes, SARIF mapping.
- Markdown report layout.
- Python minimum (`>=3.12`).

## Verifying the migration

```bash
python -m oss_policy_kit --version          # expect 5.2.0+
python -m oss_policy_kit profiles --family multi --format json
python -m oss_policy_kit evaluate --target . --profile cra-eu-ready-1 \
  --output-dir ./out/cra --fail-on degraded
```
