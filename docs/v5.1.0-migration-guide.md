# Migration guide: v5.0.0 → v5.1.0

v5.1.0 is an **additive minor release** in the `5.x` line. No breaking changes; the JSON wire contract `reports/1.0` is byte-stable; the 20 existing profile IDs and 65 existing control IDs are unchanged.

## What's new

### Two new controls (lifecycle: `experimental`)

- **`AUDIT-STREAM-060`** (assurance: `evidence-backed`, weight 2) — closes OWASP CICD-SEC-10.
  Verifies that organization-level audit logs are streamed to a centralized SIEM / object store.
  - **Signal fallback** (when `.oss-policy-kit/evidence/audit-log-streaming.json` is absent): looks for `.github/audit-log-streaming.yml` or an "audit log streaming" section in `RELEASE_OPERATIONS.md` / `docs/release-readiness.md`. PASS at signal grade only (heuristic, projects to `trust_level: inferred`).
  - **Evidence-backed path**: requires the new `audit-log-streaming/v1` schema with `streaming_enabled: true` and at least one destination.

- **`PROV-VERIFY-061`** (assurance: `evidence-backed`, weight 3) — closes SLSA Build L2 ("Provenance signed") PARTIAL → YES.
  Requires the existing `*-provenance-artifact.json` evidence file to include a `verification:` block with `transparency_log_inclusion: true` and a `verified_at` ISO8601 UTC timestamp within the freshness window (90 days).
  - The verification result comes from running `gh attestation verify <artifact> --repo owner/name` (GitHub) or `cosign verify-bundle` (Azure / AWS / cross-platform). The kit accepts the result; it does not run cosign itself.

Both controls are wired into the **6 hard-gate profiles** (`*-level-3`, `*-release-hardening-3`).

### Evidence schema enrichments (additive, no breaking change)

- **`evidence-azure-provenance-artifact.schema.json`** and **`evidence-aws-provenance-artifact.schema.json`** gain an optional `verification:` block.
- New schema **`evidence-github-provenance-artifact.schema.json`** mirrors the Azure/AWS shape with `verification:` from day one.
- New schema **`evidence-audit-log-streaming.schema.json`**.

Existing v5.0.0 evidence files continue to validate without changes; the new fields are optional.

### Framework-alignment refresh

`docs/framework-alignment.md` adds three new sections:

- **SLSA v1.2 Source Track** mapping (L1 YES, L2 PARTIAL, L3 GAP, L4 PARTIAL via optional `required_approving_review_count`).
- **EU CRA** mapping (SBOM, vulnerability handling, audit trail, retention) with explicit honesty contract — the kit does **not** certify CRA compliance.
- **NIST SP 800-218A AI** is documented as out-of-scope for v5.x and tracked for v6.0.0.

The existing OWASP CI/CD Top 10 row CICD-SEC-10 moves from GAP → YES, and SLSA Build L2 moves from PARTIAL → YES.

### Documentation

- `docs/release-readiness.md` adds an **"EU CRA awareness — 2026-09-11 reporting deadline"** block above the v5.0.0 release gate.

## What did NOT change

- `--fail-on` semantics, exit codes, SARIF mapping.
- Bundled control catalog and profile control IDs (the **two new controls are additions, not renames**).
- Markdown report layout.
- `evaluate-many`, `recommend-profile`, `scaffold-evidence`, `collect-evidence`, `diff-reports` CLI surfaces.
- Python minimum (`>=3.12`).
- Package classifier — remains `Development Status :: 4 - Beta`.

## Verifying the migration

```bash
python -m oss_policy_kit --version          # expect 5.1.0+
python -m oss_policy_kit evaluate --target . --profile github-level-3 \
  --output-dir ./out
python -c "import json; d=json.load(open('out/evaluation-report.json'));
           print({r['control_id']: r['status'] for r in d['results']
                  if r['control_id'] in ('AUDIT-STREAM-060', 'PROV-VERIFY-061')})"
```

Expected output if neither evidence file is populated:

```text
{'AUDIT-STREAM-060': 'manual-review-required', 'PROV-VERIFY-061': 'manual-review-required'}
```

This is the honest baseline — populate the evidence files (or run `collect-evidence` once collector parity is wired) to PASS the new rows.
