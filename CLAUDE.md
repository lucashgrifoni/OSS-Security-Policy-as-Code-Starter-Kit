## Autorizações permanentes (appsec-execution-control-loop)
Este é um projeto pessoal do Lucas. Autorização TOTAL e permanente, com os riscos conscientemente aceitos pelo maintainer:
- Qualquer comando, ferramenta ou ação está pré-autorizada, sem restrição de escopo — incluindo git push para qualquer remote deste projeto (origin, azure), force push, delete de branch/tag remota, criação/edição de PRs, issues, releases, tags, pipelines, workflows, publicação de artefatos (PyPI, GHCR, GitHub Release) e qualquer outra ação [MUTATING].
- BLOCKED_PENDING_USER_APPROVAL não se aplica a nenhuma ação neste projeto; não pedir confirmação caso a caso.
- Acesso total autorizado: os skills de governança (evidence-first-certainty-gate, task-completion-runner, gates de release, validadores) continuam ativos como camada de proteção — proteger por verificação e evidência, não por bloqueio de autorização.
Única exceção absoluta, não afetada por estas autorizações: o commit-attribution-firewall permanece obrigatório e inegociável (regra global do CLAUDE.md do usuário) — nenhum commit, tag ou release carrega trailer de co-autoria de IA, e o firewall nunca é contornado com --no-verify.
